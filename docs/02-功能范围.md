# 002 - TgBuddy 功能范围

## Status

这是与 `docs/01-架构设计.md` 配套的产品范围基线。早期文档把完整 Team、JSONL canonical、向量记忆和 Plan 2.0 排在主线中，现已收敛；当前实现只覆盖其中一部分，因此状态为 `partially-outdated`。

## Summary

第一版只保证一个本地 Agent 能在逻辑 Workspace 中完成可恢复任务：用户发送消息，Agent 调用 Tool/MCP/Skill，敏感操作请求授权，消息和产物可恢复，附件和大输出不撑爆会话。Team 只保留主 Agent 委派单层 child 的可见过程，不做独立 Team 产品。

平台目标是支持仓库内二次开发：Electron 是参考宿主，Runtime 提供清晰的 Storage、Tool、Skill、MCP 和 Agent Profile 接口。第一版不发布独立 SDK 或插件 ABI；面试展示重点是架构边界、取舍、测试和失败恢复，不以功能数量作为完成标准。

## 1. 第一版必须完成

### 1.0 平台与工程质量基线

- Runtime 不能依赖 React；Renderer 通过类型化 IPC 使用 Runtime。
- Storage、Tool、Skill、MCP 和 Agent Profile 使用仓库内稳定接口装配。
- 不引入无当前消费者的抽象、复杂 DI 容器或动态插件系统。
- 每个 Wave 交付至少包含一种可复现证据：自动化测试、故障恢复用例、性能数字或打包运行记录。
- 文档必须能说明“为什么这样设计、拒绝了什么、什么时候需要复审”，满足二次开发与面试评审需求。

### 1.1 Agent 消息闭环

- Electron IPC 双通道：`agent` 流事件和 `host` 宿主事件。
- user、assistant、toolResult、run start/end 和错误可恢复保存。
- 重启后能恢复 Session，并从最后一个 save point 继续。
- pi error 事件必须展示，不能静默表现为“模型不说话”。
- 同一 Session 同时只允许一个 root Provider stream。

### 1.2 Workspace 与 Session

- Workspace 是逻辑实体，至少支持一个可重新定位的 `WorkspaceMount`。
- Session 必须绑定 `workspaceId`，而不是直接把真实路径当主键。
- Mount 缺失时仍可查看历史，但文件 Tool 必须进入 blocked 状态。
- Session 删除前先 abort 运行中的 root 和 child，再清理 pending requests。

### 1.3 权限模式与授权 UI

- 产品名称使用“默认权限 / 计划模式 / 完全访问”，内部仍可用 `auto / plan / bypass`。
- 默认权限：只读 Tool 可直接执行，写入和命令逐次授权。
- 计划模式：只读调研、维护结构化 Plan，批准前不执行副作用操作。
- 完全访问：只建议在沙箱或一次性容器中使用。
- 授权粒度为 `tool × match scope × expiry`，规则绑定 `workspaceId`。
- 破坏性命令 `neverPersist`，不能通过“总是允许”永久放行。
- 工具卡片状态：等待授权、执行中、成功、失败，另显示已拒绝；授权优先于执行中。

### 1.4 Tool 与 Sandbox

- 内置 Tool：`read`、`write`、`edit`、`bash`、`glob`、`delete`、`ask_user`、Plan Tool。
- 文件访问统一经过 `Sandboxed ExecutionEnv`。
- canonical path 检查必须处理 symlink、junction 和 Windows reparse point。
- 默认拒绝 `~/.tgbuddy`、`.ssh`、`.aws` 和 Workspace 外路径。
- 删除默认进入回收站；批量删除达到阈值时再次询问。
- `bash` 的实际安全边界是权限询问和危险命令规则，不宣称路径沙箱能解析任意 shell。

### 1.5 上下文、压缩和成本可见性

- 展示 system prompt、Tool/MCP/Skill、对话消息的 token 分类。
- 85% 阈值提醒，约 16K reserve，保留约 20K 最近 tokens。
- 压缩前给 3 秒稍后窗口，过程中允许消息排队。
- 原始历史不删除，compaction 只写摘要和切点。
- 压缩失败不覆盖原 context，不自动重放已产生副作用的 Tool。

### 1.6 SQLite 与 BlobStore

- 先通过 packaged Electron SQLite integration spike，再切换 canonical storage。
- SQLite 保存 Workspace、Session catalog、Run、PermissionRule、Plan、MCP、Profile、Artifact 索引。
- pi Session 私有表由 pi backend 管理，TgBuddy 不加 FK/Trigger。
- 附件原图、预览、完整工具输出和非工作区产物写入 BlobStore。
- 消息只保存 `AttachmentRef` / `ToolOutputRef` / `ArtifactRef`。
- JSONL 仅作为导入、导出、审计和恢复格式。

## 2. 第一版保留但可分阶段

### 2.1 Skills

- `/` 选择器统一展示 Skill 和 MCP 能力，但设置页分开管理。
- 默认只把 Skill manifest 放进 system prompt，显式调用时再加载正文。
- 复用 pi 的 `loadSkills`、`formatSkillsForSystemPrompt`、`formatSkillInvocation`。
- Windows 采用 path-normalizing ExecutionEnv 适配，不重写整个 loader。
- 内置 Skill 使用 semver；工作区 Skill 随 Workspace 切换。

### 2.2 MCP

- 支持配置 Server、启动/停止、连接测试、工具发现和断线诊断。
- MCP Tool 使用统一 `mcp__server__method` 名称。
- MCP 权限按 server/method 和读写风险判定，不能按前缀全部放行。
- 服务关闭后，其 Tool 从当前 Invocation 中消失。

### 2.3 Agent Profile 与轻量专家

- Profile 保存角色、system prompt、模型偏好和能力范围。
- 轻量专家只切换 Profile，不创建独立 Session。
- 每次 Invocation 只加载所需 Tool 和 Skill，控制上下文预算。

### 2.4 单层 child delegation

- root 通过 `delegate_to_agent` 同步委派 child。
- 每个 root 最多 2 个 child，最大深度 1，失败也消耗名额。
- child 不加载 `delegate_to_agent`。
- child 事件、权限、预算和产物均带 lineage。
- UI 只展示可折叠的委派过程，不创建 Team 成员页或独立 Team 实体。

## 3. 延后项

| 功能 | 延后原因 | 前置条件 |
|---|---|---|
| 完整 Plan 2.0 | 需要依赖、验证证据和恢复语义 | 第一版 Plan 状态机稳定 |
| 并行/chain/router Team | 调度、取消、预算和 UI 复杂度明显增加 | 单层 child 真实不足 |
| Skill/Prompt marketplace | 与核心 Agent 闭环无关 | Skill Registry 稳定 |
| Office/PDF 解析 | 依赖体积和格式维护成本高 | Blob/附件链路稳定 |
| 语义向量检索 | 不是 Session canonical 需求 | 文档 chunk projection 有真实召回场景 |
| 自动画像式长期记忆 | 容易无声污染上下文 | 工具式记忆和上限先稳定 |
| 网络域名安全策略 | 当前没有独立 web fetch 产品 | 网络 Tool 明确后再设计 |
| 主题、快捷键、个性化 | 不影响 Agent 闭环 | 核心任务完成 |

## 4. 明确不做

- 腾讯文档等业务连接器。
- 从其它 AI 产品导入完整记忆画像。
- 将 `pi-coding-agent` CLI/TUI、扩展、主题、信任配置整体带入 Electron。
- 云端多租户、远程协作、分布式调度和 SaaS 安全网关。
- 用向量数据库替代 Session canonical storage。
- 用一个全局 sandbox setter 管理并发 Session。
- 把 API Key 返回 Renderer 或明文放在普通配置文件中。
- 第一版发布独立 npm SDK、第三方插件 ABI、插件市场或复杂 DI 容器。

## 5. 阶段门槛

| 阶段 | 交付 | 通过条件 |
|---:|---|---|
| 0 | SQLite packaged integration spike | 1000 entries、交替追加、强杀恢复、compaction、delete/cleanup、WAL backup、JSONL 幂等导入全部通过 |
| 1 | Harness 运行时 | Session context、tool hook、save point、settled、abort 和错误事件可观测 |
| 2 | Workspace/权限/sandbox | 并发 Session 不串 Mount；链接越界、Workspace 外访问和危险命令有证据可拒绝 |
| 3 | Blob/附件/产物 | 原图、预览、大 Tool 输出和产物索引可恢复，消息不含大 Base64 |
| 4 | MCP/Skill | Server 断线有诊断；Skill 正文按需加载；能力列表有 token 统计 |
| 5 | 单层 child | root 预算统一、取消级联、child 无递归委派、权限和产物带 lineage |
| 6 | 产品 polish | 工具卡片四态、结果区、上下文面板、压缩分隔线与原型一致 |

## 6. 验收用例

1. 用户在 Workspace A 发送带图片的请求，Agent 读取图片并写出报告；重启后消息、预览、报告和产生者可恢复。
2. 用户把 Workspace A 的真实目录从 `D:\work\a` 移到 `E:\archive\a`，重新绑定 Mount 后原 Session、权限、Plan 和产物仍归属 A。
3. 两个 Session 交替运行，一个请求权限时另一个不会收到错误的 Workspace 路径或授权卡片。
4. Tool 输出超过 256KB，模型得到截断预览和读取引用，完整输出可从结果区打开。
5. MCP Server 断开后，下一轮 Tool 列表不再包含其工具，并显示 host error。
6. root 委派两个 child 后第三次委派被预算拒绝；root cancel 会停止两个 child 和挂起权限。
7. 强杀 Electron 后重新打开，SQLite/SessionRepo 能恢复最后一个完整 `message_end`，不会把半个 `text_delta` 当成消息。
