## QA 发现的真实缺陷（已修复并回归）

1. **P1：`SessionMeta.profileId` 从未落库（Profile 选择在真实运行中失效）**
   - 现象：设置页可创建 Profile、输入区也可选择，但 `session:list` 返回的 profileId 始终为空；
     选择后下一次 Run 不会使用所选 Profile。
   - 根因：C04 只给契约和内存仓库加了 `profileId`，`app_sessions` 表与
     `SqliteSessionRepository` 没有对应列/映射，SQLite 读写静默丢弃该字段；
     单测使用内存仓库所以未暴露。
   - 修复：迁移 `012_app_sessions_profile_id.sql` 加列；repository 的
     SELECT/INSERT/UPDATE/sessionValues/rowToSession 补齐映射（NOT NULL 列写空串）；
     新增 `sqlite-repository-sql.test.ts` 用静态断言锁住列/占位符/值三者一致，防再次错位。
2. **P2：设置页创建 Profile 后，输入区模型 chip 不刷新**
   - 现象：新增 Profile 后打开输入区模型菜单看不到它，必须重启应用。
   - 根因：`profilesAtom`/`channelsAtom` 只在 App 挂载时加载一次。
   - 修复：ModelChip 打开菜单时重新拉取渠道与 Profile 列表。
